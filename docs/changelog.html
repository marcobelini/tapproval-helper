Changelog

Every release of Tapproval Base, the helper on your computer, newest first. Starting Claude Code once updates it. Generated from the releases on GitHub, which may already hold a newer one. Security fixes are also explained on the security page.

1.1.35

2026-10-02

Tapproval Base is the computer half of Tapproval: it puts Claude Code's permission prompts on your Apple Watch, each marked with its risk, and one tap answers. Nothing is approved for you unless you ask it to be, and a CRITICAL never is.

Already installed? Starting Claude Code once updates it.

Since 1.1.34

  • A card says where it comes from. It names the repository, not the folder Claude happens to work in. A worktree or a subfolder used to stand in for it on most prompts. The session's title goes beside it, so you know which conversation is asking.
  • An integration call says what it does: "Check PR status" instead of "ccd_pr · get status".
  • Integration calls that only read are marked LOW (get, list, search and so on). Writes, unknown calls and anything risky keep their marks.

Already installed? Starting Claude Code once updates it.

Since 1.1.30: fixes from a whole-codebase review

  • SAFE now means it reads and runs nothing new. Some commands that wrote a file (cat x 1> ~/.zshrc), ran a program of the caller's choosing (PATH=…, git -c core.pager=…, sed 'w …') or printed a credential (gh auth status -t, ${GITHUB_TOKEN}, App Store Connect .p8 keys) were rated SAFE. With --quiet they went through without asking. They now ask. Writing CLAUDE.md or .claude/commands asks too.
  • Pairing is for a watch. A program on this computer can no longer claim a pairing key for itself, and no enrolment can take over the iCloud key's place.
  • The relay proves what it says, not only who it is. Its proof now covers each answer, and a signed request covers its query too, so on shared Wi‑Fi nobody in between can change a card or an address. Older watches keep working.
  • Changing the key keeps the away address, instead of reopening the tunnel every few minutes under the old secret.
  • A question answered from the wrist in a message you sent from the watch reaches Claude, instead of being reported as unanswered.
  • Today is your day, counted and clocked in your own time zone. One odd line in a transcript no longer blanks Sessions or Usage.
  • Uninstall cleans up fully, and the release scripts stop at a failed step instead of reporting success.

Tapproval Base 1.1.29

2026-09-30

Tapproval Base is the computer half of Tapproval: it puts Claude Code's permission prompts on your Apple Watch, each marked with its risk, and one tap answers. Nothing is approved for you unless you ask it to be, and a CRITICAL never is.

Already installed? Starting Claude Code once updates it.

Since 1.1.28

  • The away address really survives a restart. The program that holds the tunnel open wrote its messages into a pipe only the helper read, so when the helper stopped — every update, every restart — the tunnel died within a second and the address was lost. It writes to its own log now, in its own session, and the next helper takes it over. After this update, the address changes one last time.
  • A bad moment no longer replaces a good tunnel. The check that decides whether to keep a tunnel allows a few tries, and when the address does change the watch's Connection screen says so until the watch has it.
  • A stopped Mac bridge is named: "The iCloud route is off", instead of nothing.
  • --status troubleshoots. python3 ~/.tapproval/ClaudeRiskClassifier.py --status shows the relay, the iCloud route, whether the away address answers from the internet, Tailscale, the watch, every problem the helper has noticed, the one next step, and where the log is. What each row on the watch means: https://tapproval.thoughtfulsteward.org/apple-watch-claude-code.html

Since 1.1.25

  • Security: every request now proves its own key. Several requests on one connection were answered with state the first one left behind. A request without a key could ride the key the request before it had proved. On the travel address, Cloudflare shares connections between callers, so that was a way in without a key. It came in with signed requests in 1.1.21, and this release fixes it.
  • Answers from the wrist register again. The same flaw made an answer that followed a check for new cards read that check's empty body. It was refused, and the answer was lost.
  • Works with your iPhone off. Without its iPhone, a watch can reach your computer only over the internet. The travel address now stays the same across helper updates and restarts, and only a restart of the Mac itself changes it. A matching watch update (TestFlight build 141 and later) tries every route at once.
  • Uninstall stops the travel tunnel too, now that it outlives the helper on purpose.

Since 1.1.20 — a security release

  • Your key no longer crosses the network. A watch signs each request instead of sending its key, each signature is good once, and the helper proves itself in its answer; the watch learns an address only from such an answer. The old way is still accepted for one release, for watches that predate it.
  • No pairing door where iCloud carries the key. A Mac with the iCloud bridge never offers a key on the network, the network door hands out a revocable device key rather than the main one, and a reset replaces the main key.
  • Commands that change things are no longer read as reads. gh auth logout, fly apps create, swift package update, gcloud config set; awk system(…), rg --pre, git diff --output, find -fprint; and wrappers such as sh -c "rm -rf /", env rm -rf ~ or ( rm -rf ~ ) are now judged by what they do. A write to a path through .. is judged where it lands.
  • Messages from the watch reach their session's permission prompts on plugin installs, a new session needs the watch's key even from this machine, and a crash in the helper's request handling is reported instead of lost.
  • Faster and lighter: a session's thread is read from the end of its transcript (one 227 MB transcript: 1.6 GB and 1.6 s → 45 MB and 0.02 s).

Tapproval Base 1.1.20

2026-09-24

Tapproval Base is the computer half of Tapproval: it puts Claude Code's permission prompts on your Apple Watch. When Claude stops to ask before doing something that needs your say-so, the question lands on your wrist, marked with its risk, and one tap answers it.

Nothing is approved for you unless you ask it to be, and a CRITICAL never is. Answer on the wrist, or the usual terminal prompt appears exactly as it would without this installed.

Install

Tell Claude Code on your computer:

Install the Tapproval plugin from marcobelini/tapproval-helper

Already installed? Starting Claude Code once updates it.

Then get the watch app, free: https://apps.apple.com/app/tapproval/id6805869018 (outside the EU for now — the beta works everywhere: https://testflight.apple.com/join/dW1tYBQG).

You need an Apple Watch and Claude Code on a Mac or Linux machine.

Since 1.1.16

  • Sessions started from the watch reach the watch. A Terminal opened from inside a Claude Code session handed that session's markers to every window, and a session that thinks it is another's child saves no transcript — so New session started a session the phone could see and the watch never did. The helper now sheds those markers, and the window it opens unsets them too.
  • New session answers in under a second. The helper tried to script Terminal first and waited four seconds for a permission it cannot ask for; the watch gave up and said the computer did not answer, about a session that had started. It now opens the window the way that needs no permission, first.
  • An update reaches a busy helper. An outdated helper that answered slowly was left running beside its installed update; it is now asked again, patiently, and replaced.
  • What you said stays in the thread. Your latest message stays at the head of a session's thread on the watch, and Claude Code's own notes no longer pass as yours or hide what you wrote.
  • The watch knows which sessions are open on your computer, so it can say, where you type, that a message from the wrist runs beside that open session rather than inside it.
  • An end-to-end check (e2e_new_session.py, in the product repository) now starts a real session the way the watch does before a change to how sessions start is published.

What it is

Python, standard library only: no dependencies to audit and none to install. No server, no account, no analytics. A tool that reads your sessions and carries your approvals should be one you can read, so all of it is here.

Loopback is the only free pass: every other caller, on your Wi-Fi or not, must present a token issued to one device.

Since 1.1.4

  • Sessions carry the names the Claude app gives them, and name the repository rather than a session's worktree. Starting a new session offers your real projects — no worktrees, no folders only scheduled runs use.
  • Messages from the watch work after a restart. Started at login with a bare search path, the helper could not find Claude Code; it now looks where the installers put it, and says so on the watch if Claude Code is truly missing.
  • A second copy of the helper no longer crashes. A slow start-up check could launch a second helper beside a busy first one; it now sees the port is taken and leaves it.
  • An update put off for a waiting card is tried again on every start, never while a card is waiting.
  • The helper knows which code it runs however it was started, and the watch's Connection screen shows where that code is from.
