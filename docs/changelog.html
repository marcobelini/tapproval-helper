Changelog

Every release of Tapproval Base, the helper on your computer, newest first. Starting Claude Code once updates it. Generated from the releases on GitHub, which may already hold a newer one. Security fixes are also explained on the security page.

1.1.71

2026-10-23

Tapproval Base is the computer half of Tapproval: it puts Claude Code's permission prompts on your Apple Watch, each marked with its risk, and one tap answers. Nothing is approved for you unless you ask it to be, and a CRITICAL never is.

Already installed? A terminal install updates itself when Claude Code starts. A plugin install updates when auto-update is on: in Claude Code, type /plugin, open Marketplaces, choose tapproval and pick Enable auto-update.

Since 1.1.70

  • Encryption between your watch and your computer, ready for watch app 2.1. On your Wi-Fi the helper now also listens encrypted, with a certificate of its own that the watch learns only from an answer your computer has proven; the watch then accepts that certificate and no other. Away from home, what passes through the travel tunnel is sealed so that Cloudflare, which carries it, sees only scrambled data. Watches before 2.1 keep working as before, unencrypted, until they update.
  • Details stored in your iCloud are encrypted too, once the matching bridge is installed.

Since 1.1.58

  • Pairing is closed to programs on your own computer. A program on this computer could pose as a watch on your network by reaching the helper through a second address of the same computer. During a pairing window, it could then answer its own cards. Every address of this computer now counts as this computer.
  • More commands reach your wrist instead of being allowed quietly. With --quiet, a few commands that change things were read as harmless, so they were allowed without asking you. Now they ask: a command after a & with no space before it, fd -x, in-place edits with combined flags (such as sed -ri), gh api calls that send data, and git config changes. MultiEdit's text is now checked the way Edit's is.
  • Your settings file stays a link. If your Claude Code settings file is a link into a dotfiles folder, setup now writes through the link instead of replacing it with a copy.
  • An update interrupted by the network keeps your install. The new copy is downloaded beside the old one and swapped in only once it is complete.
  • A card waits as long as the terminal does. In one case a card left the wrist after an hour while the terminal kept waiting; now both wait a day.
  • A message sent again over the other route runs once. If a message or a new session was retried through the away address, it no longer arrives twice.
  • The session list loads faster on computers with many past sessions.
  • The README says plainly that a buzz while Tapproval is closed needs a Mac, and why.

  • A plan started from the wrist shows its plan, and a question, command, plan or answer always arrives whole.
  • Safer answers. The hook believes only its own relay. Each card takes exactly one answer. "Always allow" is written only where Claude Code offered it.

Since 1.1.30: fixes from a whole-codebase review

  • SAFE now means it reads and runs nothing new. Some commands that wrote a file (cat x 1> ~/.zshrc), ran a program of the caller's choosing (PATH=…, git -c core.pager=…, sed 'w …') or printed a credential (gh auth status -t, ${GITHUB_TOKEN}, App Store Connect .p8 keys) were rated SAFE.   • The relay proves what it says, not only who it is. Its proof now covers each answer, and a signed request covers its query too, so on shared Wi‑Fi nobody in between can change a card or an address. Older watches keep working.
  • Changing the key keeps the away address, instead of reopening the tunnel every few minutes under the old secret.
  • A question answered from the wrist in a message you sent from the watch reaches Claude, instead of being reported as unanswered.
  • Today is your day, counted and clocked in your own time zone. One odd line in a transcript no longer blanks Sessions or Usage.
  • Uninstall cleans up fully, and the release scripts stop at a failed step instead of reporting success.

Since 1.1.20 — a security release

  • Your key no longer crosses the network. A watch signs each request instead of sending its key, each signature is good once, and the helper proves itself in its answer; the watch learns an address only from such an answer. The old way is still accepted for one release, for watches that predate it.
  • No pairing door where iCloud carries the key. A Mac with the iCloud bridge never offers a key on the network, the network door hands out a revocable device key rather than the main one, and a reset replaces the main key.
  • Commands that change things are no longer read as reads. gh auth logout, fly apps create, swift package update, gcloud config set; awk system(…), rg --pre, git diff --output, find -fprint; and wrappers such as sh -c "rm -rf /", env rm -rf ~ or ( rm -rf ~ ) are now judged by what they do. A write to a path through .. is judged where it lands.
  • Messages from the watch reach their session's permission prompts on plugin installs, a new session needs the watch's key even from this machine, and a crash in the helper's request handling is reported instead of lost.
  • Faster and lighter: a session's thread is read from the end of its transcript (one 227 MB transcript: 1.6 GB and 1.6 s → 45 MB and 0.02 s).

Since 1.1.16

  • Sessions started from the watch reach the watch. A Terminal opened from inside a Claude Code session handed that session's markers to every window, and a session that thinks it is another's child saves no transcript — so New session started a session the phone could see and the watch never did. The helper now sheds those markers, and the window it opens unsets them too.
